# 构建与验证说明

## 验证层次

| 层次 | 可说明的结论 | 不能替代 |
| --- | --- | --- |
| 源码与配置检查 | 文件结构、接口、宏和 SysConfig 配置的静态事实 | 编译、烧录或功能验收 |
| CCS 构建 | 指定提交在指定工具链下可编译链接 | 烧录成功、传感器接线正确或控制效果 |
| 烧录与启动 | 指定镜像写入目标板并启动 | 完整题目流程与性能验收 |
| 实机功能测试 | 在记录的板卡、赛道、供电、球/车起始条件下的实际表现 | 未覆盖工况的泛化结论 |

本次项目介绍整理未重新运行构建、未烧录，也未进行赛道实测。因此不在这里报告新的通过项或性能数值。

## CCS 构建复现建议

1. 记录仓库提交号和工作区是否干净。
2. 安装与 `.cproject` 元数据匹配的 CCS、TI Arm Clang、MSPM0 SDK 和 SysConfig。
3. 导入根目录 CCS 工程，检查 SDK/SysConfig 产品发现路径。
4. 按 `mpu6050-oled-hardware-i2c.syscfg` 生成外设初始化文件，构建 `Debug`。
5. 保存完整构建输出、工具版本、Flash/SRAM 摘要及生成文件状态。

如果本机使用的 SDK 或 SysConfig 版本不同，应先检查工程是否仍可重现，不要直接覆盖生成代码来消除构建差异。

## 实机记录模板

每轮至少记录以下信息，便于将结果和固件关联：

```text
日期 / 操作者：
Git 提交或固件 SHA256：
目标板与电机驱动版本：
工具链 / SDK / SysConfig：
题目任务与赛道条件：
起始位置、方向、供电：
烧录结果与启动检查：
任务完成状态、用时、停车位置：
故障/异常现象与原始日志位置：
```

没有保留原始条件与固件标识的口头结果，不应被写成当前 GitHub 提交的定量验收结论。
